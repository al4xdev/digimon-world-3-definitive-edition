it is borrowed**. The repository is public, so this is how it stays license-compliant (MIT/BSD require
keeping the copyright notice). Code in `psxstack/` has its own `docs/THIRD_PARTY.md`.

### The last 8 holdouts (issue #55)
Ours; theirs; the idea taken:
- `src/stitshop/stitshop_800859C0.c` `stitshop_info_create_windows`; `src/stitshop/info.c` `STITSHOP_createInfoWindows`: a column counter of its own with x set in the arrows' loop, and the line's y as an inline helper (FAKE).
- `src/fightstg/fightstg_8008D3B4.c` `fightstg_rules_get_stats`; `src/fightstg/stats.c` `FIGHTSTG_computeStats`: one `s16 *` over the stat totals and the equipment (FAKE), the equipment base set once, a lookup in each accessory branch, the enemy's stats as an inline helper.
- `src/stcrdshp/stcrdshp_8008300C.c` `stcrdshp_run_booster`; `src/stcrdshp/pack_open.c` `STCRDSHP_runPackOpen`: the booster's steps as inline helpers with their own locals, step 52's last index as `(page + 1) * 8 - 1` with the first index apart.
- `src/shocktst/shocktst_80082DA0.c` `shocktst_convert_table`; `src/shocktst/shocktst.c` `SHOCKTST_convertText`: `times` holding the table's start, each pair's second byte through the next pair's pointer (two FAKEs).
- `src/fightstg/fightstg_model.c` `fightstg_model_mesh_draw`; `src/fightstg/fightstg.c` `FIGHTSTG_drawMesh` (`setMeshTexture`, `drawMeshPolygons`): the texture command and the face loop as inline helpers, a `u32` command, the face block left by breaks (`LOOP_BLOCK`), a `?:` for the UVs, the draw state's lit/gouraud meanings.
- `src/wfightts/wfightts_800A7A90.c` `wfightts_digimon_menu_update`; `src/wfightts/wfightts.c` `WFIGHTTS_fighterList`: a break after each pad case, a counter per line loop, the blink test split.
- `src/fieldstg/fieldstg_80085590.c` `fieldstg_background_update_visible`; `src/fieldstg/map_streamer.c` `FIELDSTG_pickViewTiles`: y's offset as y less its tile's start, `col` reused by the clearing loop (FAKE).
- `src/fieldstg/fieldstg_80087DB0.c` `fieldstg_manager_update`; `src/fieldstg/field.c` `FIELDSTG_updateField` and its step helpers: the update split into per-step inline helpers with two `LOOP_BLOCK` early exits.
