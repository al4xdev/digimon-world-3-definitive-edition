# velvet-live

Experimental. Plays a MIDI score through the game's own sequencer (LIBSND, ticked
every vsync). Not a pre-rendered WAV, not a disc patch, no source change.

```sh
tools/venv/bin/python tools/music_lab/velvet/play.py
```

It starts `build/port-sdl/dw2003 --window` on its own debug socket
(`/tmp/velvet-live.sock`). Other agents' games are not attached. When the title
music is up, the playing sequence is pointed at the score in `sound_buffer_1`
(free at the title; entry 0 is COMMON, entry 2 holds the title bank). The samples
are whatever bank the title already loaded — the notes are the score, the timbre
is the game's.

Stay on the title screen. Starting a game reloads a bank over that pointer.

`solo.py` mutes one part at a time on that same window (`next`, `mute N`, `solo N`, `reset`). Numbers are 1..8 in the order play.py assigned.

The MIDI is read from `~/Downloads` and is not copied into the tree.

## Now in the game (2026-11-17)

The score and the bank edits are generated by `tools/gen_velvet_music.py` (reads the MIDI, never copies it) into the
gitignored `port/game/definitive_velvet_music.inc`; `port/game/definitive_velvet_music.c` and four hooks in
`src/main/sound.c` (PC_PORT) put them in the room's own bank (id 72, a copy of BGM031). `cmake` runs the generator at
configure time; run it by hand after changing a constant: `tools/venv/bin/python tools/gen_velvet_music.py --apply`
(then rebuild). `DW3_VELVET_MIDI` overrides the MIDI path. Without MIDI or disc the room keeps its old music.

play.py is now the quick way to listen to the same data without rebuilding (it takes the score and the tone edits from
the generator):

```fish
tools/venv/bin/python tools/music_lab/velvet/play.py --smooth on     # softened (the generator's constants)
tools/venv/bin/python tools/music_lab/velvet/play.py --smooth off    # the mix as first accepted: hard attacks, cut releases, no reverb
tools/venv/bin/python tools/music_lab/velvet/play.py --reverb 90     # another reverb depth (0-127) for this listen
```

Offline (headless, for numbers only, never shipped): `--wav render/x.wav --seconds 50` renders the score,
`--probe` plays one 1 s note per part instead. `analyze.py` and `analyze_probe.py` (run with
`uv run --with numpy python ...`) compare two renders.
